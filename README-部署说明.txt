【本次修复 · v111z76｜聊天记录顺序与老卡片重复】
症状：
  ① 以前发的消息跑到最新一条消息旁边（越进房间越多，12 条能变 36 条）；
  ② 往期的特殊卡片（代买 / 查岗 / 红包 / 转账 / KOMO 卡）反复出现在最新消息点。
原因：
  ① 老版本写进历史的行没有 data-created-at，而写盘合并把「缺时间戳」当成 at=0 一律排到
     最末尾；恢复历史 / 翻「更早记录」/ 重绘回执时又给这些行补上 Date.now()，
     于是「磁盘上没有、内存里有」两份身份对不上，每进一次房间就复制一份并挤到最新一端。
  ② 代买卡的历史判定写成「房间在前台就跳过」，卡片落在分页窗口外（>100 行）时 DOM 里
     找不到，就当成没有，在末尾重新补一张。
修复：
  ① 缺时间戳的行改为「沿用左边最近的时间戳原地不动」，不再沉到最后、也不补 Date.now()；
     磁盘与 DOM 两份用「弱身份」兜底合并，不会再复制。
  ② 特殊卡片重建时带上副本记录里的真实时间，按时间插回原来的位置；历史判定不再看前台。
  ③ 进房间时先跑一次幂等修复：把已经损坏的历史去重、老消息挪回时间轴开头。
     跑第二遍不改任何东西，用户数据不会被反复改写。
